# C4 (PlantUML)

C4 model views (system context, container, component, dynamic, deployment) written with the C4-PlantUML macros bundled in the engine. Use the `c4` format; for AWS service icons inside C4, see `aws-c4` (icon set {{AWS_ICONS_VERSION}}).

## When to use

- **System context**: the system, its users and the external systems it talks to.
- **Container**: applications, data stores and their responsibilities inside one system.
- **Component**: the building blocks inside one container.
- **Dynamic**: a numbered interaction flow over the static elements.
- Plain UML or flowcharts are simpler in `plantuml`; AWS-branded containers in `aws-c4`.

## Building blocks

- Wrap the diagram in `@startuml` … `@enduml` and include one bundled C4 library level:
  `!include <C4/C4_Context>`, `!include <C4/C4_Container>`, `!include <C4/C4_Component>`,
  `!include <C4/C4_Dynamic>` or `!include <C4/C4_Deployment>` (each level includes the lower ones).
- People and systems: `Person(alias, "Label", "Description")`, `System(…)`, `System_Ext(…)`,
  `SystemDb(…)`.
- Containers: `Container(alias, "Label", "Technology", "Description")`, `ContainerDb(…)`,
  `ContainerQueue(…)`, `Container_Ext(…)`.
- Components: `Component(alias, "Label", "Technology", "Description")`, `ComponentDb(…)`.
- Boundaries: `System_Boundary(alias, "Label") { … }`, `Container_Boundary(alias, "Label") { … }`,
  `Enterprise_Boundary(…)`.
- Relationships: `Rel(from, to, "Label", "Technology")`, `Rel_D`, `Rel_R`, `BiRel`, `Rel_Back`.
- Layout and legend: `LAYOUT_TOP_DOWN()`, `LAYOUT_LEFT_RIGHT()`, `SHOW_LEGEND()`, `title …`.

## Refused here (and what to use instead)

| Refused | Why | Use instead |
|---|---|---|
| Including C4-PlantUML from GitHub by address (`raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/…`) | Remote fetch | The bundled `!include <C4/C4_Container>` (and siblings) |
| `!includeurl` or any `!include` of an `http(s)` address | Remote fetch | Inline content or bundled `<…>` stdlib includes |
| Icons or sprites by address (`<img:` + URL, `$sprite` loaded from a URL) | Remote fetch | AWS icons via `AWSPuml/` (see `aws-c4`), or inline sprites |
| Environment reads (`getenv`), DTD/entity declarations | Data leak / XXE | Literal values in the source |

## Examples

Container view with a boundary:

```hermetic-example format=c4 output=svg
@startuml
!include <C4/C4_Container>
title Orders - container view
Person(customer, "Customer", "Places orders")
System_Boundary(shop, "Shop") {
  Container(web, "Web App", "TypeScript, React", "Order UI")
  Container(api, "Orders API", "Node.js", "Validates and stores orders")
  ContainerDb(db, "Orders DB", "PostgreSQL", "Orders and lines")
}
System_Ext(payments, "Payment Provider", "Card payments")
Rel(customer, web, "Uses", "HTTPS")
Rel(web, api, "Calls", "JSON/HTTPS")
Rel(api, db, "Reads/writes", "SQL")
Rel(api, payments, "Charges", "HTTPS")
SHOW_LEGEND()
@enduml
```

System context, as PNG:

```hermetic-example format=c4 output=png
@startuml
!include <C4/C4_Context>
Person(user, "Analyst", "Reads reports")
System(reporting, "Reporting", "Builds monthly reports")
System_Ext(warehouse, "Data Warehouse", "Source data")
Rel(user, reporting, "Requests reports")
Rel(reporting, warehouse, "Queries")
@enduml
```
